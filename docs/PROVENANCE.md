# Clean-Room Provenance

## Public repository boundary

This candidate contains independently authored application source, tests, configuration, diagrams, synthetic data, and documentation. It was implemented from a neutral technical specification and public product documentation.

The public candidate excludes:

- Private instructional content and evaluation material
- Institution-provided templates or source files
- Educational institution names, logos, and repository branding
- Historical PDFs, Word documents, screenshots, and grade evidence
- Historical credentials and tokens
- Captured transit vehicle fixtures and private CSV files
- Private runtime logs and source-audit records

## Independent schema and implementation

The public edition uses an independently designed relational table named `vehicle_observations` and a neutral field model centered on `observation_id`, `vehicle_id`, `stop_sequence`, and `observed_at`.

The following components were independently authored for this candidate:

- Python collector and MySQL writer
- Java 21 embedded Debezium service
- MongoDB event, observation, and latest-state sink
- Flask API and browser interface
- Docker Compose configuration
- Synthetic data generator and analysis
- Tests, validation scripts, architecture diagram, and documentation

## File-by-file review

A private comparison reviewed every public text and source file against the available historical source material. No candidate file had a similarity score of 0.35 or higher. Exact matching lines in Java and Maven files were limited to standard imports, dependency identifiers, and conventional build markup. No substantive copied source was identified in the Python collector, Flask application, Java CDC implementation, browser interface, tests, or documentation.

The private comparison report is retained outside the public candidate.

## Synthetic data

All committed JSON and CSV data is deterministic and generated by `scripts/generate_synthetic_data.py`. Vehicle and trip identifiers are synthetic. The public candidate contains no captured transit fixture or historical CSV dataset.

## Historical private-prototype analysis

An earlier private educational prototype used a preserved 6,767-observation data slice across 36 trips and 13 vehicles over approximately 4.85 hours. The slice was not the full runtime. A later audit excluded three incomplete trips and produced the corrected primary findings of 45.40 minutes for 20 complete trips and 7.56 km/h average point-to-point speed.

Those captured records and private educational materials are not included here. The public synthetic dataset is separate and does not reproduce the historical analysis.

## Validation distinction

A pre-release architecture using the same five-service pattern passed end-to-end Docker validation on September 4, 2026.

The first independently rewritten public candidate was then tested from a fresh extraction on September 5, 2026. Its core pipeline worked after a diagnostic CDC restart, but its untouched fresh start failed because the MySQL health check accepted the temporary socket-only initialization server and CDC readiness stayed positive after the Debezium engine terminated.

This corrected candidate changes MySQL readiness to require TCP port 3306, replaces file-based CDC readiness with a failure-aware HTTP health check, exits the CDC process when the embedded engine terminates unexpectedly, and adds an empty-volume integration validator. The exact v3 archive passed that untouched fresh-start test on September 5, 2026, with zero CDC restarts, 45 passing Python tests, seven passing Java tests, and matching synchronized counts of 84 rows/events in the three storage checks.
